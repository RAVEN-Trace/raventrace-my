# RAVEN SIGNAL DESIGN SYSTEM V6

## Core idea

**Dark for tension. Light for understanding.**

Raven is not a dashboard, a hacker interface, a SaaS product or a generic news template. It is a public truth-navigation system built around investigative credibility, narrative forensics and evidence clarity.

## Product promise

**Faham cerita → nampak framing → semak bukti → buat kesimpulan sendiri.**

Public-facing Raven must feel like a smart investigator sitting beside the reader and explaining a difficult issue in ordinary Malaysian language.

## Visual grammar

- **Dark Raven** = orientation, investigation identity, tension, narrative framing.
- **Paper Raven** = reading, evidence, explanation.
- **Cyan** = Raven checked / evidence / active navigation.
- **Amber** = missing context, caution, incomplete state.
- **Muted red** = contradiction or serious disputed state only.
- **Grey** = unknown / unresolved, not failure.
- **Serif** = story, major editorial headlines, claim statements.
- **Sans** = explanation, controls, plain-language UI.
- **Mono** = source IDs and forensic metadata only.

## Interaction grammar

Raven repeatedly teaches the reader the same reasoning path:

1. **Apa orang kata?**
2. **Apa rekod tunjuk?**
3. **Apa yang cerita tak sebut?**
4. **Apa yang belum tahu?**
5. **Apa kesimpulan paling selamat?**

Interactions must improve understanding. No decorative animation.

## CASEFILE architecture

Every future case uses four permanent lenses:

- **FAHAM** — Apa benda sebenarnya berlaku?
- **NARATIF** — Apa cerita yang sedang dibentuk?
- **BUKTI** — Apa rekod boleh sahkan?
- **STATUS** — Apa yang berubah sekarang?

Deep sections such as people, timeline, money, governance, investments and sources sit beneath these lenses.

## Narrative Forensics signature pattern

Every public narrative unit should read as:

**ORANG KATA**
→ **APA REKOD TUNJUK**
→ **JURANG CERITA**
→ **RAVEN VERDICT**
→ optional **Kenapa Raven kata begitu?**

Do not accuse intent merely because a framing effect exists. Neutralise, do not counter-spin.

## Public-language rule

**Simplify language, not evidence.**

A teenager, makcik/pakcik or reader who does not follow politics daily should understand the main point on first read.

Technical terms may remain for accuracy, but plain-language explanation comes first or is available in context.

## Mobile rule

Mobile is a primary design target, not a collapsed desktop layout.

Aim for one core idea per screen:

**Claim → Record → Gap → Verdict → Why?**

Use short chunks, strong typography, thumb-friendly controls and progressive disclosure.

## Page roles

- Homepage = **Truth Desk / truth navigator**
- Investigations = **Choose what you want to understand**
- CASEFILE = **Explain first, evidence deeper**
- Narrative Forensics = **Show how stories shape perception**
- Newsroom = **What changed / what did not / what remains unclear**
- Story pages = **One question, one clear answer**
- Money = **Data explainer**
- People = **Legal/process state, not guilt shorthand**
- Timeline = **What happened / why it matters / status**
- Source Room = **Proof layer**
- Methodology = **How Raven checks things**
- Corrections = **How Raven fixes itself**
- Tips = **Bring Raven something to check**
- About = **Why Raven exists**

## Hard exclusions

Avoid:

- cyberpunk/neon hacker theatre
- crypto dashboards
- SaaS landing-page patterns
- endless card walls
- meaningless motion
- random stock imagery
- decorative data visualisation
- technical jargon as a prestige signal
- red as a default alarm colour

## Success test

A mobile visitor arriving from Threads should be able to:

- understand the issue within roughly 10 seconds,
- understand the difference between a claim and the record within roughly 30 seconds,
- know where to inspect evidence without needing specialist knowledge,
- leave feeling more capable of judging the narrative independently.

**RAVEN determines what the evidence supports. VANTA//FORGE determines how the reader experiences and understands it.**
